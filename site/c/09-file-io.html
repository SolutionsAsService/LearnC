Files

Write a file, read it back, and the bug the original example had.

The original read_file.c declared char ch and compared it with EOF. fgetc returns an int, either a byte from 0 to 255 or EOF (-1), and a char cannot hold all 257 values. We measured both ways it fails:

  • Where char is unsigned (ARM: Raspberry Pi, Android), EOF becomes 255, which never equals -1. The loop never ends and prints \377 forever.
  • Where char is signed (x86), a file containing the byte 0xFF stops early. The input a\xffb printed only a.

gcc -Wall -Wextra does not warn about it; -Wconversion does. The repo also lacked example.txt, so the old program only ever printed “Could not open the file.” This version writes its own file first.
